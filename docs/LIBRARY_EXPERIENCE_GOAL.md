# Library 便捷接入与组件外观配置 — 增量 Goal 执行规格

日期：2026-11-15。状态：已按用户授权完成 M1–M4；L01–L12 全部通过。实际命令、独立消费者与视觉证据见 library-experience-progress.md 和 library-experience-acceptance.md。

## 1. 目标与基线

让开发者在 Playground 选择组件、调整内容及外观、验证交互后，能够导出当前配置及基于 `@enterprise/agent-ui` 公开入口的接入代码，在仓库外的真实 React/Node 消费项目重现效果。

原 MVP M1–M4 与 J01–J40 的完成记录保留；本次使用独立的增量验收项。沿用 `GOAL_EXECUTION_SPEC.md`、Handoff、Agent API 设计、UI Review、I18N_REQUIREMENTS 的工程、安全和视觉规则，不重新执行无关功能开发。

启动时核对的缺口（现已补齐）：

- 复制窗口只有 A2UI JSON、运行配置、REST 请求，没有 Library 输入及前后端接入代码。
- Library 文档已存在于 API & Docs，但组件配置与接入指南之间缺少直接入口。
- 多数组件只有业务字段；Text/Button 有少量 variant，CapabilityProfile 有业务配色，没有统一外观模型。
- Runtime 已有项目 CSS tokens；公开运行配置主要支持 light/dark，尚无完整的主题覆盖传输。

## 2. 范围与交互

### 2.1 Library 便捷入口

复用“复制接入代码”窗口，增加 Library 分类，包含：

1. 输入：适用时生成 template.create；自定义原始响应保留为 a2ui 输入，不强行转换模板。
2. Node/TypeScript：公开 server 入口、真实 manifest 加载、Adapter 创建/应用/清理。
3. React/TypeScript：公开 react 入口、Provider/Client/独立 Host、连接后提交、Action/Error、重连重放及清理。
4. 主题与外观：与输入配套的配置及用途说明。

草稿/当前预览沿用已有显式选择；代码、运行配置、外观配置必须取自同一份所选快照，不能把历史预览消息与新草稿配置混合。代码保留业务数据、完整 Action 信封及组件/模板版本。可复制和下载生成文件，并跳转对应 Library 指南。

模板流式场景保留步骤及顺序；后续 patch 的示例必须是可以继续当前 run 的真实输入。不能将若干原始消息直接冒充 template.patch。示例区分 Playground REST 调试和独立 Library 接入。

已上传插件在导出时说明 manifest、已批准制品和独立 Host 的部署要求，代码生成不把 bundle 导入业务主页面。

### 2.2 三层外观配置

| 层级 | 内容 | 归属 |
| --- | --- | --- |
| 主题 | 字体预设、基础字号、品牌/正文/次要/背景/边框及状态色、圆角、间距密度 | 可信 Host/应用配置 |
| 组件外观 | 文字层级、字号、字重、行高、文字色、背景色、边框色/宽度、圆角、内边距、间距、对齐 | 按组件能力声明的项目配置 |
| 业务配色 | 风险色阶、图表系列色、雷达图当前/目标色 | 既有业务 Schema 或显式扩展 |

语义选项为默认；高级面板开放有范围的数值和颜色。字体首期使用受控系统字体预设，不增加远程字体上传/加载。颜色允许语义 token 和经过校验的颜色值；不接受任意 CSS 字符串、选择器、资源 URL 或脚本表达式。

组件显式覆盖优先于主题，主题优先于组件默认值；清除覆盖表示继承。复合组件内的标题、正文等配置按稳定 componentId 或声明的具名样式槽定位，不能依赖 DOM 顺序或任意 CSS 选择器。

不是所有属性对所有组件生效。组件目录增加类型化的外观能力元数据，Playground 依此展示控件。未知插件默认只具备明确实现的容器能力；内部文字/图形样式需插件声明并实现，不能承诺通过父级 CSS 改变所有插件内容。

### 2.3 Playground 表现

- 在现有配置区增加“内容 / 外观”，布局和视觉语言沿用现有工作台。
- 外观按“文字、颜色、容器、布局”分组；不可适用项不展示，每项可恢复继承，支持重置该组件外观。
- 组合组件提供可读的节点/样式槽选择，不引入完整拖拽设计器。
- 预览主题独立于工作台外壳主题，放在预览工具区的紧凑面板中。
- 外观编辑沿用草稿/应用模型；切换查看方式不产生虚假脏状态。颜色/字号操作可在当前预览内更新外观，更新不重建业务组件、不丢用户输入、不重复发出 Action。
- 外观/主题/选中节点纳入草稿与预览快照；切换组件保留各自草稿，切换语言不改业务数据。

## 3. 架构与兼容规则

先核对锁定版本的官方公开 Schema/API，再确定平台外观配置的具体字段及存储位置，并记录决策。

- 官方 Core 继续拥有 Surface/Data Model；项目外观配置不维护第二套业务状态。
- 官方已有能力使用实际受支持的字段。平台额外能力使用明确命名、版本化的项目配置/扩展；不修改官方 Schema，不将自定义 style 当作官方通用属性。
- 主题和组件外观通过校验后的通道传给 Preview Host、embedded Host 及嵌套 Sandbox；不能依赖主页面样式穿透 iframe。
- Playground 和独立 Library Host 使用同一份 Schema、默认值、token 映射和渲染逻辑。
- 上传插件的新增主题能力通过本项目 SDK 明确提供。旧插件继续可加载，未声明的内部能力显示为不支持；更新两个示例插件验证新合同。
- 明确处理包/Host/manifest 的版本匹配；如新增字段不被旧 Host 支持，应升级对应版本并明确拒绝不兼容组合，不能静默忽略。
- Library 仅通过公开 package exports 使用；服务端、浏览器和 Host 入口的依赖边界保持清楚。
- 不引入任意 CSS 编辑、远程字体管理、拖拽搭建、生产发布或新企业鉴权。
