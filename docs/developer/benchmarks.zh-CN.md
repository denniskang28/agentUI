# Benchmark 使用与测量边界

在 Benchmarks 选择组件、模式、负载、实例数、频率和持续时间，然后开始测试。Native / Sandbox 可单独运行，Compare Both 使用相同初始数据、相同更新序列和配置依次运行，不同时运行两份测试。测试开始会清理原工作台预览；离开页面会销毁独立测试预览，停止会取消待执行更新和旧 Mock。

热力图支持 100 / 1,000 / 10,000 个数据单元格（每行四个指标），表格支持相同数量的记录，均可选择 1 / 3 / 5 个独立 Surface 实例、1 / 10 / 30 / 60 Hz 和 1–60 秒。大数据采用可视窗口，原始 DataModel 仍保存完整数据；不具备可扩展数据结构的插件使用原始模板，不伪造负载。未知插件需有可更新字段；无法生成更新的模板会明确失败。

| 指标 | 实际边界 |
|---|---|
| 冷启动就绪 | 每个模式触发重置/首次渲染，到所有实例可信包装层报告首次 React layout commit / ready；包含目录加载与插件模块加载。新建实例，浏览器缓存保持自然状态，不代表强制清空 HTTP 缓存 |
| 首次内容显示 | 第一个实例有非空、非零尺寸的内容，完成 React 提交及两次 requestAnimationFrame 后的显示机会；这是浏览器可测的近似，不能证明硬件像素呈现或任意第三方组件的业务内容完整 |
| 更新 P50 / P95 | Preview Host 收到更新，到全部目标实例实际 React 提交。包装层使用自身 performance.timeOrigin + performance.now()，转换到 Host 时钟；排除 Sandbox 返回通道耗时。原始样本另保留主工作台开始请求到收到确认/测量回执的 RTT |
| Action 分段 | 在实时预览中真实点击后，记录点击→Host、Host→工作台、实际 Mock 等待/响应、响应→组件提交和总往返。总往返包含回执通道；无点击时不可用 |
| 长任务 | PerformanceObserver 支持时，采集本次运行 Preview Host 可观察到的 longtask 记录、数量和总时长；不声称完整覆盖或准确归因到 opaque Sandbox |
| 内存 | performance.memory 可用时保存 JS heap 快照、初始值和差值；浏览器可能量化或合并进程数据，不能精确归因到某个 iframe。不支持则为 null |
| 错误 | 导出 Load / Render / Bridge / Measurement / Other 诊断数量和原文；一个根因可产生不同阶段诊断。构建在选取已安装组件之前发生，本次运行未执行构建，build 为 null，实际构建错误仍在 Plugins 页 |

初始阶段等待全部实例 ready，但仅等待第一个实例的显示机会：屏外 Sandbox 的动画帧可能被浏览器暂停。更新测量检查所有实例提交。跨文档高精度时钟仍存在量化误差，允许 1 ms 的时钟分辨率容差，容差内的负间隔归零，原始事件时间和 `clockToleranceMs` 保留；明显非法时间不接受。

调度按目标时间发送，不等待上一个更新完成后再追加一个间隔。落后一个周期或有八个请求未完成时跳过该周期，不突发补发。被新更新覆盖的提交标记 superseded；跳过、覆盖、超时和失败均不计入成功样本 P50/P95。请同时比较实际频率、成功样本数、被覆盖数和跳过数，不能仅凭低延迟判断吞吐表现。

导出 `benchmark/1.0` JSON 包含浏览器、插件 JS 产物字节数、配置、runId、初始组件时序、每次更新的目标与时间、统计范围、实际点击记录和错误。插件 JS 字节数是构建产物大小；内置组件为 null。不要把单次本机结果当成通用性能结论，也不预设 Native 比 Sandbox 快固定百分比。

可信测量通道独立于 A2UI Wire / 业务 DataModel。普通预览仍按官方 Core 确认回执完成；仅 Benchmark 显式等待实际组件测量。旧构建产物若没有提交探针，会超时并显示不可用，需要通过正常上传入口重新编译，不回退到虚构计时。

验证：`tests/e2e/benchmarks.spec.ts` 使用真实 Docker 编译产物、两种运行模式、万级负载、真实点击、停止销毁以及模块加载错误恢复；`tests/unit/measurement.test.ts` 检查多实例完成、时钟、过期回执、覆盖和目标校验。截图及本机原始数据保存在 `artifacts/visual/benchmarks`。
