# Repository privacy / 仓库隐私

公开仓库保留应用源码、测试、锁文件、可复现脚本、通用部署说明及不含内部信息的验收记录。真实服务器配置和原始运维记录保存在本地忽略目录 `.private/`，不属于克隆后启动 Playground、插件或两个 Chatbot Demo 的依赖。

## 本地保留的资料

| 内容 | 本地位置 | 处理方式 |
| --- | --- | --- |
| 真实环境配置、Nginx/systemd 和部署脚本 | `.private/deployment/` | 保留实际配置用于维护；公开示例使用保留的测试地址 |
| 原始部署说明和脱敏前的文档 | `.private/deployment/`、`.private/documents/` | 保留历史操作细节，公开文档只保留通用说明 |
| 含机器路径、会话信息的日志、浏览器 trace 和测试报告 | `.private/evidence/` | 仅本地验收使用，可由现有验证命令重新生成 |
| 历史改写前的恢复归档和提交映射 | `.private/backups/` | 仅用于本地恢复，不能上传或作为公开附件 |
| 文件级清单和处理原因 | `.private/inventory.json` | 记录原路径、本地路径和文件指纹 |

迁移时保留了部分被忽略的本地符号链接，以兼容原部署和证据生成命令。新检出不需要这些链接。部署到实际服务器时，从私有资料准备对应配置；通用部署流程见现有 Library 与 Demo 部署指南。不要直接把整个工作目录打包公开。

运行中的 `.runtime/` 保留在原位并继续忽略，避免影响本地插件服务。`dist/`、本地依赖、生成的安装包、Host 发布目录和参考站点提取目录继续按原规则忽略；生成资源也可能含构建时注入的环境地址。原始设计 ZIP 不修改。

## 后续提交

- `.gitignore` 排除 `.private/`、真实 `.env` 和私钥文件；经过脱敏的 `.env.example` 可以提交。Git 忽略规则不能阻止 `git add -f`，也不会清理已经存在的历史。
- 测试与公开配置使用本机地址、保留的测试 IP 或 `example.test` 域名，不能写入实际部署地址。
- 提交前检查 `git diff --cached`、`git ls-files`，尤其注意新增日志、截图、环境文件和归档。截图和二进制附件需要人工检查，文本扫描不能保证发现所有敏感内容。
- 提交者邮箱也会公开。需要隐藏个人邮箱时，为该仓库设置适当的公开邮箱或匿名邮箱。
- 清理历史后相关提交哈希会改变。若旧历史已经发布，远端、其他克隆及平台缓存需要另行处理；本地历史改写不会自动清除外部副本。

本次本地清理检查了所有可达提交的文件内容和提交元数据，并保留必要功能测试。原始运维资料与恢复归档只在忽略目录中保存。
