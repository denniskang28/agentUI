# Implementation decisions

## 2026-11-14

- Keep the existing Goal and M1–M4 scope when adding bilingual requirements; J36–J40 supplement J01–J35. Locale is platform configuration and never rewrites Agent data.
- Use pinned official Core 0.15.0 plus official React Surface/Node renderer. Preserve official schemas; project-specific React views reproduce the reference's visual tokens. No edits to vendor source.
- Keep uploaded JavaScript out of the main app. Native creates a plugin-owned React root inside the separate Preview Host; Sandbox mounts the identical built artifact in a nested opaque-origin iframe. Both receive the same SDK action/locale context, and locale changes update the root rather than mounting it again.
- Use Fastify and in-memory preview sessions, with local artifact/registry cache under ignored `.runtime`. This is a local development service, not an authenticated public API.
- Use Docker with no network, no writable root, non-root UID, dropped capabilities and resource/time limits for user compilation. The first uncached Docker Hub image pull timed out. A locally cached official `node:24-bookworm-slim` image built successfully; user-build isolation was unchanged.
- Generate JSON Schema validators server-side as bundled ESM. Browser Ajv compilation conflicted with CSP. Keep CSP without `unsafe-eval` and remove runtime schema compilation instead of weakening the policy.
- Reference extraction stays separate in `.reference` and original ZIP is untouched. The first screenshots caught loading/connection states too early; formal captures must wait for actual rendered content and use matching states. Those early images are not a completed visual acceptance report.
- iframe documents must use content height, not `body {height:100%}` plus a resize padding increment. Otherwise each resize acknowledgement increases the frame again. Override height only in Preview Host/Sandbox; preserve the main app layout.
- A separate `preview.connected` and application ACK distinguishes HTTP acceptance from official Core application. Paint timing remains separate and does not imply nested plugin readiness; Benchmark validation must respect this scope.
- Resolve render policies per Surface/Component through platform `componentPolicies`, not by adding wire commands or blocking an entire Surface. Use the installed Core's explicit component `catalogId` for mixed-catalog Surfaces; no invented aggregate catalog is necessary. Real browser tests cover progressive/on_complete/live together.
- Action polling uses a session-bound opaque cursor independent of SSE IDs. A mode-switch reset creates a fresh run and replays received history; after reset every batch must include runId so an old untagged response cannot land in the new instance.
- Keep developer documentation as checked-in Chinese/English Markdown and display the same files in the UI with a text-only renderer. Execute the documented Python, TypeScript and cURL clients against real previews for all three scenarios.
- Keep message parser diagnostics independent of UI locale: stable error codes and original line/column/UTF-16 offset, with raw engine diagnostics retained. JSON.parse remains the strict acceptance gate; pinned jsonc-parser 3.3.1 supplies reliable positions only after parsing fails. A localized error link focuses and selects the actual source position in the existing editor. This avoids loading an additional editor runtime solely for error navigation.
- Store validation conditions and toast keys, not translated strings, so switching locale updates visible transient UI. Approval retries retain an idempotency key for the same intent; a business resultVersion distinguishes consecutive receipts with identical status and releases pending only on a new result.
- Sandbox initially retains its frame height until plugin content commits. Reporting the empty pre-commit body shrank the frame to 32px before its real layout arrived; browser hit testing intermittently delivered the first click to the outer iframe. An attempted pointer-events gate did not resolve this and was removed. The trusted build wrapper now reports React layout commits; ResizeObserver ignores empty pre-commit sizes and still supports existing nonempty artifacts. Ten consecutive real Heatmap upload/render/click tests passed after this change; no test retries or synthetic click fallback were added.
- Installed Core accepts unknown component types under its default rules, but the official React renderer skips unresolved nodes. The Preview adapter resolves those types to an inert platform placeholder in a private rendering Catalog, retaining original IDs. Known schemas and missing Catalog errors remain official Core behavior. Raw API validation/session history/playback/export are unchanged; the resolved Inspector tree can show the platform placeholder. No vendor code or wire command was added.
- Core owns mutable DataModel objects. Clone incoming values at validation/rendering boundaries so later patches cannot mutate earlier message snapshots or the server's history during validation. Tests compare the original snapshot independently and exercise streamed updates/replay.
- Returning from JSON to a template form requires the generator to reproduce the whole message sequence with recovered values. Extra Surfaces, altered trees or changed stream steps stay in JSON with a localized explanation. Merely viewing a matching form retains the exact JSON text; only actual form edits regenerate it.
- Uninstall checks the Catalog IDs of running components, not only the selected gallery entry. An external Agent can render a different component or a combined Surface; uninstalling an active plugin clears that run and its timers. Tests use a genuinely uploaded plugin with an actual interval to verify native effect cleanup, Sandbox frame disposal, continued updates and refresh replay.

- Benchmark owns a visible Preview Host rather than reusing the hidden Playground frame. Compare Both destroys the previous mode before starting the same fixture in the next mode; starting also clears the main preview to prevent background instances from competing.
- Trusted build wrappers report actual uploaded-root ready/layout commits and a two-animation-frame display opportunity. These are platform telemetry, never A2UI messages or business fields. Native and Sandbox report their own event timestamps; per-request/per-component tracking rejects stale IDs and marks overwritten work superseded. Normal application ACK semantics remain unchanged.
- Offscreen opaque frames can stop receiving animation frames. First render observes the first instance's display opportunity while waiting for all instances to report ready; updates still measure every instance's commit. Physical presentation and arbitrary plugin semantic readiness remain beyond this probe's guarantee. Cold timing includes catalog loading through epoch-based timestamps and does not claim a cleared HTTP cache.
- Send updates on an absolute schedule, with at most eight pending requests and no catch-up bursts. Skip late cycles, retain actual rate/raw results and exclude superseded/timeouts/errors from successful-sample percentiles. Each generated update changes a displayed fixture field. Benchmark omits large wire histories instead of retaining thousands of full 10k-cell messages.
- Use visible windows for large DataTable and Heatmap fixtures, retaining full Core data. The demo Heatmap schema now permits 2,500 rows / 10,000 metric cells. Small/default fixtures retain the existing presentation.
- Capture real clicks and Mock response commits in both execution modes. Cross-document clock quantization occasionally produces a tiny negative interval; preserve event timestamps and declare a 1 ms tolerance, clamping only sub-resolution negatives rather than dropping a genuine interaction. Clearly invalid timestamps remain rejected.
- Long-task observations and heap snapshots are best effort and explicitly scoped to what Preview Host/browser can expose, without individual Sandbox attribution. Build count is null because Benchmark uses already-installed artifacts. Load/Render/Bridge/Measurement/Other diagnostics and source text are exported; no measured zero is invented for a stage outside the run.
- Sandbox registers its private port before awaiting dynamic module import, allowing module failures to report PLUGIN_LOAD_ERROR through the validated channel. Runtime failure ends the current measurement explicitly, rather than waiting for a synthetic successful sample or an unrelated Host paint. Real load failures and same-page recovery are covered in both modes.

- Share HTTP request validators with OpenAPI and derive standalone message shapes from the SDK's public Zod exports. Keep the raw official schema untouched. Publish actual response/event/status-code contracts and verify real Fastify/Docker responses against them. Canonical idempotency sorts object keys recursively, preserving array order and field values.
- TTL cleanup is timer-driven, emits session.destroyed and closes SSE even without another request. Keep only a bounded-lifetime expired-ID tombstone for a clear 410 response. Use Fastify preClose to end streams before waiting for server shutdown. Forward actual asynchronous plugin errors separately from Core ACKs; neither a 202 nor Core ACK implies completed paint.
- Discovery now reports a Catalog ID for basic components too. Client template generation must distinguish enterprise/plugin shapes by actual component identity, not mere Catalog-ID presence. The new contract test generates and officially validates messages from every discovered entry.
- External mode replay and Reset carry the current selected locale; reset events synchronize the UI locale too. Language changes alone still update the existing plugin instance, without resetting business/local state. Late API failures from previous runs are ignored.
- Match the reference Plugins page with a dense table, selected detail section, schema-field rows and Schema/Actions/Templates/Build-log tabs. Keep full raw Schema available in a disclosure. Replace upload uses the real manifest/catalog and file picker, compiles a new artifact, and only replaces the entry on success. Tests upload and replace actual unknown source through the UI before checking the rendered result.
- The generic array editor reads enum and numeric constraints from the discovered business schema, including when no rows remain. The demo Heatmap declares its three actual group values as an enum so the same generic control renders the reference's group selector; it is not keyed to a hardcoded plugin ID. Uploaded business text and enum values remain unchanged across language switches.

- Final visual review restores reference heading line-height 1.12, Docs left alignment/220px navigation/22px heading, and Benchmark 1100px width. Text uses reference 15px body type and actual short-content height instead of a 32px Host minimum. Empty pre-commit plugin frames still retain their established lifecycle protections.
- Capture scripts wait for actual preview nodes and frame paint opportunities. The old reference Text locator matched a textarea before preview completion; it now waits for the reference preview paragraph. This changes only evidence capture, never the original reference.
- Final acceptance combines the Chinese unmasked comparisons, English matrix, detail/state screenshots and real interaction regression. It does not derive a fidelity percentage from pixel differences or claim production authentication/persistent sessions.
