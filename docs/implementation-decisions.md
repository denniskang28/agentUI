# Implementation decisions

## 2026-11-14 — Public comparison deployment

- Deploy baseline and integrated chat under separate `/demos/` prefixes on the existing IP, preserving the root site. Vite base controls assets, business fetch and EventSource URLs; variant-specific conversation storage prevents the two demos reusing one session ID on the same Origin.
- Run each backend as its own non-root systemd service on loopback, with locked Linux dependencies and production static files. The integrated Host has its own site and exact parent allowlist, retaining nested opaque Sandbox and Host-only Native execution. No business credentials are forwarded to that Host.
- Use the existing browserId/getRandomValues mechanism for the embedded Host and secure random bytes for the handwritten approval key, supporting the requested HTTP demo. Keep deterministic demo Agents, identity and in-memory business semantics explicit.
- Validate public health responses as JSON with status=ok. On this server, loopback Nginx plus an IP Host header reached another existing server block and returned unrelated HTML; use the actual public URL and assert its body instead of counting HTTP 200 alone.

## 2026-11-14 — Recover the discovered component catalog

Playground 的内置初始列表仅作接口加载前的回退，不能在一次发现请求失败后永久冒充完整目录。发现失败使用独立、双语的列表状态和有上限的退避间隔持续恢复；导航与窗口/网络恢复触发同步。成功响应相同时复用已有列表引用，避免打断编辑和预览。安装/卸载仍使用现有 reload 合同；不执行或重新安装上传代码。

## 2026-11-14

- Keep the existing Goal and M1–M4 scope when adding bilingual requirements; J36–J40 supplement J01–J35. Locale is platform configuration and never rewrites Agent data.
- Use pinned official Core 0.15.0 plus official React Surface/Node renderer. Preserve official schemas; project-specific React views reproduce the reference's visual tokens. No edits to vendor source.
- Keep uploaded JavaScript out of the main app. Native creates a plugin-owned React root inside the separate Preview Host; Sandbox mounts the identical built artifact in a nested opaque-origin iframe. Both receive the same SDK action/locale context, and locale changes update the root rather than mounting it again.
- Use Fastify and in-memory preview sessions, with local artifact/registry cache under ignored `.runtime`. This is a local development service, not an authenticated public API.
- Use Docker with no network, no writable root, non-root UID, dropped capabilities and resource/time limits for user compilation. The first uncached Docker Hub image pull timed out. A locally cached official `node:24-bookworm-slim` image built successfully; user-build isolation was unchanged.
- Generate JSON Schema validators server-side as bundled ESM. Browser Ajv compilation conflicted with CSP. Keep CSP without `unsafe-eval` and remove runtime schema compilation instead of weakening the policy.
- Reference extraction stays separate in `.reference` and original ZIP is untouched. The first screenshots caught loading/connection states too early; formal captures must wait for actual rendered content and use matching states. Those early images are not a completed visual acceptance report.
- iframe documents must use content height, not `body {height:100%}` plus a resize padding increment. Otherwise each resize acknowledgement increases the frame again. Override height only in Preview Host/Sandbox; preserve the main app layout.
- A separate `preview.connected` and application ACK distinguishes HTTP acceptance from official Core application. Paint timing remains separate and does not imply nested plugin readiness; Benchmark validation must respect this scope.
- Resolve render policies per Surface/Component through platform `componentPolicies`, not by adding wire commands or blocking an entire Surface. Use the installed Core's explicit component `catalogId` for mixed-catalog Surfaces; no invented aggregate catalog is necessary. Real browser tests cover progressive/on_complete/live together.
- Action polling uses a session-bound opaque cursor independent of SSE IDs. A mode-switch reset creates a fresh run and replays received history; after reset every batch must include runId so an old untagged response cannot land in the new instance.
- Keep developer documentation as checked-in Chinese/English Markdown and display the same files in the UI with a text-only renderer. Execute the documented Python, TypeScript and cURL clients against real previews for all three scenarios.
- Keep message parser diagnostics independent of UI locale: stable error codes and original line/column/UTF-16 offset, with raw engine diagnostics retained. JSON.parse remains the strict acceptance gate; pinned jsonc-parser 3.3.1 supplies reliable positions only after parsing fails. A localized error link focuses and selects the actual source position in the existing editor. This avoids loading an additional editor runtime solely for error navigation.
- Store validation conditions and toast keys, not translated strings, so switching locale updates visible transient UI. Approval retries retain an idempotency key for the same intent; a business resultVersion distinguishes consecutive receipts with identical status and releases pending only on a new result.
- Sandbox initially retains its frame height until plugin content commits. Reporting the empty pre-commit body shrank the frame to 32px before its real layout arrived; browser hit testing intermittently delivered the first click to the outer iframe. An attempted pointer-events gate did not resolve this and was removed. The trusted build wrapper now reports React layout commits; ResizeObserver ignores empty pre-commit sizes and still supports existing nonempty artifacts. Ten consecutive real Heatmap upload/render/click tests passed after this change; no test retries or synthetic click fallback were added.
- Installed Core accepts unknown component types under its default rules, but the official React renderer skips unresolved nodes. The Preview adapter resolves those types to an inert platform placeholder in a private rendering Catalog, retaining original IDs. Known schemas and missing Catalog errors remain official Core behavior. Raw API validation/session history/playback/export are unchanged; the resolved Inspector tree can show the platform placeholder. No vendor code or wire command was added.
- Core owns mutable DataModel objects. Clone incoming values at validation/rendering boundaries so later patches cannot mutate earlier message snapshots or the server's history during validation. Tests compare the original snapshot independently and exercise streamed updates/replay.
- Returning from JSON to a template form requires the generator to reproduce the whole message sequence with recovered values. Extra Surfaces, altered trees or changed stream steps stay in JSON with a localized explanation. Merely viewing a matching form retains the exact JSON text; only actual form edits regenerate it.
- Uninstall checks the Catalog IDs of running components, not only the selected gallery entry. An external Agent can render a different component or a combined Surface; uninstalling an active plugin clears that run and its timers. Tests use a genuinely uploaded plugin with an actual interval to verify native effect cleanup, Sandbox frame disposal, continued updates and refresh replay.

- Benchmark owns a visible Preview Host rather than reusing the hidden Playground frame. Compare Both destroys the previous mode before starting the same fixture in the next mode; starting also clears the main preview to prevent background instances from competing.
- Trusted build wrappers report actual uploaded-root ready/layout commits and a two-animation-frame display opportunity. These are platform telemetry, never A2UI messages or business fields. Native and Sandbox report their own event timestamps; per-request/per-component tracking rejects stale IDs and marks overwritten work superseded. Normal application ACK semantics remain unchanged.
- Offscreen opaque frames can stop receiving animation frames. First render observes the first instance's display opportunity while waiting for all instances to report ready; updates still measure every instance's commit. Physical presentation and arbitrary plugin semantic readiness remain beyond this probe's guarantee. Cold timing includes catalog loading through epoch-based timestamps and does not claim a cleared HTTP cache.
- Send updates on an absolute schedule, with at most eight pending requests and no catch-up bursts. Skip late cycles, retain actual rate/raw results and exclude superseded/timeouts/errors from successful-sample percentiles. Each generated update changes a displayed fixture field. Benchmark omits large wire histories instead of retaining thousands of full 10k-cell messages.
- Use visible windows for large DataTable and Heatmap fixtures, retaining full Core data. The demo Heatmap schema now permits 2,500 rows / 10,000 metric cells. Small/default fixtures retain the existing presentation.
- Capture real clicks and Mock response commits in both execution modes. Cross-document clock quantization occasionally produces a tiny negative interval; preserve event timestamps and declare a 1 ms tolerance, clamping only sub-resolution negatives rather than dropping a genuine interaction. Clearly invalid timestamps remain rejected.
- Long-task observations and heap snapshots are best effort and explicitly scoped to what Preview Host/browser can expose, without individual Sandbox attribution. Build count is null because Benchmark uses already-installed artifacts. Load/Render/Bridge/Measurement/Other diagnostics and source text are exported; no measured zero is invented for a stage outside the run.
- Sandbox registers its private port before awaiting dynamic module import, allowing module failures to report PLUGIN_LOAD_ERROR through the validated channel. Runtime failure ends the current measurement explicitly, rather than waiting for a synthetic successful sample or an unrelated Host paint. Real load failures and same-page recovery are covered in both modes.

- Share HTTP request validators with OpenAPI and derive standalone message shapes from the SDK's public Zod exports. Keep the raw official schema untouched. Publish actual response/event/status-code contracts and verify real Fastify/Docker responses against them. Canonical idempotency sorts object keys recursively, preserving array order and field values.
- TTL cleanup is timer-driven, emits session.destroyed and closes SSE even without another request. Keep only a bounded-lifetime expired-ID tombstone for a clear 410 response. Use Fastify preClose to end streams before waiting for server shutdown. Forward actual asynchronous plugin errors separately from Core ACKs; neither a 202 nor Core ACK implies completed paint.
- Discovery now reports a Catalog ID for basic components too. Client template generation must distinguish enterprise/plugin shapes by actual component identity, not mere Catalog-ID presence. The new contract test generates and officially validates messages from every discovered entry.
- External mode replay and Reset carry the current selected locale; reset events synchronize the UI locale too. Language changes alone still update the existing plugin instance, without resetting business/local state. Late API failures from previous runs are ignored.
- Match the reference Plugins page with a dense table, selected detail section, schema-field rows and Schema/Actions/Templates/Build-log tabs. Keep full raw Schema available in a disclosure. Replace upload uses the real manifest/catalog and file picker, compiles a new artifact, and only replaces the entry on success. Tests upload and replace actual unknown source through the UI before checking the rendered result.
- The generic array editor reads enum and numeric constraints from the discovered business schema, including when no rows remain. The demo Heatmap declares its three actual group values as an enum so the same generic control renders the reference's group selector; it is not keyed to a hardcoded plugin ID. Uploaded business text and enum values remain unchanged across language switches.

- Final visual review restores reference heading line-height 1.12, Docs left alignment/220px navigation/22px heading, and Benchmark 1100px width. Text uses reference 15px body type and actual short-content height instead of a 32px Host minimum. Empty pre-commit plugin frames still retain their established lifecycle protections.
- Capture scripts wait for actual preview nodes and frame paint opportunities. The old reference Text locator matched a textarea before preview completion; it now waits for the reference preview paragraph. This changes only evidence capture, never the original reference.
- Final acceptance combines the Chinese unmasked comparisons, English matrix, detail/state screenshots and real interaction regression. It does not derive a fidelity percentage from pixel differences or claim production authentication/persistent sessions.

- An IP-based HTTP page lacks `crypto.randomUUID`. Generate request UUIDs and sandbox nonces through `crypto.getRandomValues`, preserving secure randomness without requiring HTTPS for the demonstration. The Expense Approval example similarly uses a 128-bit random idempotency key. Verify actual public rendering and Action completion rather than treating an HTTP 200 or successful build as proof of a working demo.

## 2026-11-14 — Chatbot Library and comparison demos

- Deliver one package with three public subpaths, rather than three mutually versioned packages. ESM bundles include project implementation and accompanying declarations; exact upstream runtime dependencies remain declared. The tarball is installed into independent npm consumers, not linked to monorepo source.
- Keep the business shell, deterministic agents, orchestrator and actual demo service identical in two applications. Replace only presentation/Action adapters, renderer and deployment inputs. Check file hashes against an explicit difference whitelist; do not claim percentage savings.
- Reuse the original Catalog, Policy and PluginMount in a separate static Host. Set plugin asset origin through Context, preserving the original Preview default. Approved build artifacts and manifest are exported once; deployed chat does not run Playground or Builder.
- Server Core validates bounded replay history atomically, while Host Core owns interactive state. Identity mappings contain template/version associations only. Defer schema validation of partial business data until ready, preserve explicit null despite official path-null deletion, and invalidate convenience mapping when raw structure breaks its binding.
- Distinguish repeated readiness messages from a new iframe document with documentId. React effects detach resources without permanently disposing a client that StrictMode may replay. A new run/runtime mounts a new Host/client; same-run document reload replays ordered history.
- The shared runtime reads binding notifications through official DataModel/dataContext and copies resolved values for notification snapshots, preserving plugin instance identity. Original recovery, input, locale and timer cleanup tests remain the regression boundary.
- Treat network offline/online as explicit SSE close/reconnect with the last processed cursor. UI event IDs and run IDs prevent duplicates and stale updates. Business authorization/readiness/ownership and idempotency remain backend responsibilities, even when an Action came from a genuine plugin.
- Give each Vite application its own dependency cache; sharing the default cache caused observed Outdated Optimize Dep 504 responses after dependency/build changes. Exclude generated dist declarations from the root source typecheck to avoid concurrent rebuild races.
- Keep standalone demo backends as readable TypeScript run by installed tsx; npm ci includes complete dependencies. Library and Host are compiled deployment artifacts. The supplied Node static Host server uses only Node built-ins. POSIX process groups let launchers stop descendants; the external consumer verifies ports close after deployment stops.
- Use actual fixed-viewport screenshots after scrolling to the UI. Chromium full-page capture produced distorted offscreen nested cross-origin iframe rasterization although DOM dimensions and viewport captures were correct. Do not edit UI or mask content for evidence. Retain table-internal horizontal scrolling and document reserved Sandbox height.
- Consumer health polling uses Node's HTTP client with no pooled agent. The current macOS Node 24 undici build produced an uncaught setTypeOfService EINVAL while polling terminated sockets; switching this test utility avoids the observed tooling crash without changing product transport.

以上选择均在本地授权范围内执行。新增交付的范围、18 项 Chatbot 浏览器场景、仓库外消费者与视觉证据见 chatbot-integration-acceptance.md；不把可选 RPC、生产鉴权、持久化或真实模型当作已实现能力。

## 2026-11-15 — Library experience verified design

The configuration contract above is implemented. Public-consumer verification now passes with the real 0.2.0 tarball and matching compiled Host. Draft exports combine draft data/config; preview exports use actual sent messages, the captured template/version and applied configuration. Subsequent streamed steps retain raw wire messages to avoid guessing convenience-patch semantics. Node output is an offline preprocessing script; a live backend owns one Adapter per run, authorizes full Actions and assigns fresh IDs/sequences to results. React applies returned normalized batches, reconnects/replays and cleans up its Client. Generated files use only package exports.

Appearance is applied inside the policy boundary around the actual View; an earlier outer wrapper did not reach the real DOM and was corrected. ECharts now retains its instance on data/theme changes. Host resize observes intrinsic `#root` content instead of the viewport-sized document, allowing growth and shrinkage after appearance changes. Screenshot capture must additionally wait for computed styles and resize/paint completion; an immediate capture could retain a partly painted older size despite correct eventual DOM.

The theme panel has an internal close control and a viewport-bound scroll region. Unset color controls explicitly show inheritance; a custom picker appears only after selecting a custom value. Theme font-size/radius controls share the schema's narrower limits. Complex nodes use Surface/component IDs encoded as a pair, preserving drafts without path collisions. No arbitrary CSS editor, remote font loader or plugin execution in the main application was introduced.

## 2026-11-16 — Playground response draft ownership

Local custom-response JSON belongs to the selected component draft, independently of its generated or edited template JSON. Seed it from that component's current template only when undefined; an intentionally empty draft is valid editor state. External Agent JSON remains session-owned. Merge patches into the latest draft so an asynchronous file read cannot replace unrelated later edits. Select import mode immediately, while applying the eventual content to the component that started the import. Selecting an already active scenario is a no-op; restoring template examples clears every scenario JSON override.


## 2026-11-16 — Two sources and two input formats

Preserve the existing Component templates / Custom response distinction. Add A2UI / Library templates as an independent format selector shared by both sources. Generate convenience inputs from known scenario operations; preserve custom inputs verbatim as validated batches. Explicit batch envelopes keep their own run ID, order and deduplication rules. A temporary server-side AgentUiAdapter compiles the entire sequence through genuine Core and is always disposed. Playback sends each compiled batch and its validated component policies atomically to the isolated Preview Host; compiled policies survive mode replay. There is no uploaded JavaScript in the editor and no alternate business renderer.

Format-specific template and custom drafts remain independent, including empty and invalid source text. Form edits invalidate only the active format's manual override. The JSON editor supports batch pause/step controls. Library exports keep original inputs and actual run IDs, with only sent batches for a preview snapshot; if later Mock updates differ from the original input history, export actual raw messages instead of silently dropping Action results. Appearance node discovery for Library JSON comes from actual compilation. Invalid Library drafts block copy/download until compilation succeeds. Existing external Agent sessions remain raw A2UI.

## 2026-11-18 — MCP Apps Host (MH01–MH15)

- Add a separate `@enterprise/mcp-apps-host` protocol/react/server package with pinned official ext-apps 2.0.4 and split MCP SDK 2.4.0. Zod 4 stays inside this package; existing A2UI 0.15.0/Zod 3 APIs are not migrated. Public package exports and tarballs are exercised outside the monorepo.
- Keep A2UI and MCP Apps as independent conversation channels. No HTML-to-A2UI conversion or mandatory Node A2UI translation service. The Node Gateway is a reference implementation of a language-neutral contract; Java delivery is an executable HTTP client example, not a Java Gateway.
- Use official AppBridge without a browser MCP Client: explicit tool/resource handlers call a controlled Gateway. Tools and resources share the server connection; app/model visibility intersects the backend allowlist. Server credentials remain backend-only. Trusted `callForHost` + `attach` handles an existing execution without re-executing during view mount. Browser create has explicit request-ID idempotency; no side-effect retry.
- A trusted outer Preview proxy owns a nested opaque iframe. A dedicated sandbox document receives resource-specific HTTP CSP and separate meta restrictions; original A2UI documents keep their original policy. Exact parent configuration and origin/source checks replace referrer dependency. Gateway CSP, deployment allowed origins and resource declaration all constrain access. Browser permissions/nested Apps/custom base URI are unsupported. Local Server addresses require explicit allowLocal; remote connections pin validated DNS and reject redirects.
- Each instance binds connection/run/toolCall IDs. Results wait until initialized and full input notification completes; transport identity stays stable on theme/locale changes. Different instance identities use a fresh iframe window. Teardown is bounded; business owners destroy instances explicitly, while View effect cleanup only closes its bridge so StrictMode replay can remount safely. Connection TTL handles abandoned ownership.
- The Playground records message/context callbacks as developer diagnostics. The Chatbot routes messages through its deterministic orchestrator and stores context in its session; no LLM execution claim. Optional external-link capability requires a business callback and target policy. Only inline display is advertised.
- Fixes found by real tests: normalize SDK-added `_meta` before strict Gateway parsing; use a replacement callback when inlining bundled HTML (literal `$&` in bundled JS must not expand a replacement pattern); omit JSON Content-Type on empty DELETE; refresh integrity of both local tarballs when regenerating a same-version development release.
- New workbench visual design reuses existing tokens/controls and responsive scrolling; there is no new-page original ZIP reference. Original ZIP and unrelated untracked architecture/deployment material stay untouched. Full lint remains separately reported from scoped lint because of the pre-existing untracked generator errors.

Final lifecycle review also rejects every callback after a View detaches and rejects connections finishing after Gateway disposal. Sandbox CSP is prepended inside an inert parsed document and serialized with a leading HTML doctype, preserving standards mode; actual browser policy tests verify `CSS1Compat`. Negative protocol fixtures run as a separate local Server and are excluded from the published package. Existing Chatbot tests accept environment-supplied origins so complete regression can run against fresh installed consumers without resetting unrelated long-lived services.
