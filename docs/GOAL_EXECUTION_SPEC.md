# Agent UI MVP — Goal 执行与验收约定

日期：2026-11-14。此文档定义准备启动的持续开发目标；创建本文件不代表 Goal 已启动或功能已经实现。

## 1. 目标

自主完成 Enterprise Agent UI Runtime & Plugin Playground MVP 的 M1–M4：交付本地可运行的真实前后端、官方 A2UI SDK 集成、组件模板、流式运行、动态插件上传编译、双模式预览、Action 闭环、Agent Developer API、文档及测试。

2026-11-14 追加：工作台、Preview Host、两个示例插件及面向开发者的核心说明支持简体中文 / English，执行 `docs/I18N_REQUIREMENTS.md`。此追加沿用当前 Goal；文件更新本身不解除暂停，也不表示功能已实现。

尽可能逐项还原参考 UI。以功能证据和逐页视觉比较决定完成，不以写完代码、静态展示、测试数量或未经验证的相似度分数代替交付。

## 2. 输入与优先顺序

必须阅读：

1. `docs/AGENT_UI_MVP_HANDOFF.md`：产品范围、架构和验收项。
2. `docs/AGENT_INTEGRATION_API_DESIGN.md`：API 拟议契约、交互与运行语义。
3. `docs/ui/V1_DESIGN_REVIEW.md`：参考原型必须修正的偏差。
4. `docs/ui/Agent UI Playground v1.zip`：视觉和交互参考，以压缩包内 `Agent UI Playground v2.dc.html` 为视觉基线。
5. `docs/I18N_REQUIREMENTS.md`：中英文范围、状态保持、SDK/API locale 和 J36–J40 追加验收项。

视觉方面以参考页面为准，不自行重新设计。协议、SDK、插件身份和接口内容方面，执行已确认 PRD 和评审校正。官方 SDK 的能力、导出和协议支持以实际验证为准，结果记录到兼容性文档。

原始 ZIP 保持完整。提取一份独立只读参考站点，在本地浏览器实际打开并记录各页和关键状态；实现站点与参考站点分开启动。

## 3. 自主决策

- 常规技术选型、模块拆分、文件组织、依赖安装、代码调整、测试、调试、恢复和视觉修正由执行者自行决定，不逐项征询。
- 连续完成 M1 → M4；里程碑用于执行和验证，不作为自动等待用户确认的关卡。
- 参考有遗漏时，从现有布局、Token 和交互模式补全最小必要设计；保留现有风格。
- 参考与需求冲突时，优先满足需求，尽量复用已有样式；在决策日志记下原因、方案和影响。
- 某条路线无效时，选择有证据的替代路线。按 Handoff 限制同一阻塞的不同修复尝试；达到限制后记录明确 blocker，继续能独立推进的其他工作，不循环重复失败。
- SDK 能力不足时先验证适配、官方可用 Renderer 等方案。不伪造官方接口、不把自定义渲染冒充官方集成；无法满足的验收项保持未通过。
- 缺失且无法合理推断的凭据、外部账户操作或工具强制要求本人执行时，才提出具体需要人工处理的事项；说明已完成内容及可解除阻塞的最小动作。
- 完成本地交付。公开发布、购买服务、对外发送消息、删除已有无关资料不属于本目标。

## 4. 功能完成条件

Handoff 的 J01–J35、追加的 J36–J40 和 Definition of Done 逐项有证据，并覆盖：

- 分类 Icon 组件库、场景模板、表单/JSON 切换、自定义响应及 JSON/JSONL 导入；支持组合组件和多 Surface 检查。
- 真正的 A2UI 消息校验和官方消息处理/Renderer；协议版本与实际能力有兼容性记录。
- Play/Pause/Step/Reset、有序更新，以及 progressive/on_complete/live；on_complete 必须区分数据到达与 ready 条件达成。
- TSX/ZIP 上传、验证、隔离构建、动态注册、重新上传及卸载；依赖和上传约束真实生效。
- Risk Heatmap、Expense Approval 都通过上传入口安装，未知第三插件也可以被发现和使用。
- Native 仅在独立 Preview Host 执行；Sandbox 在其内进一步隔离；主 Playground 不执行上传代码。
- 真实点击产生 Action，Mock 或外部脚本处理后返回消息，实际 UI 更新；运行模式切换及重置清理旧实例和迟到事件。
- Agent API 与 UI 共用 Schema/模板/校验；发现、模板实例化、会话、消息提交、事件/Action 接收可用。重试、顺序、连接、过期与销毁行为有测试。
- Benchmark 输出真实测量，说明采集范围和不可用指标；不使用随机值模拟正式性能结果。
- OpenAPI/API Reference、Agent Quickstart、Plugin Developer Guide、README 和可执行 cURL/Python/TypeScript 示例。
- 全工作台简体中文 / English 切换与持久化；切换保留编辑及运行状态，预览与两个示例插件同步语言，核心开发者说明双语，机器协议与用户业务内容保持原样。

## 5. 视觉还原标准

逐页复现：Playground、Plugins、API & Docs、Benchmarks，以及复制代码窗口、模式切换提示和关键错误状态。

逐项对齐：

- 页面分区、列宽、工具栏高度、间距、内外边距和滚动区域。
- 字体、字号、行高、字重、截断和换行行为。
- 配色、边框、圆角、阴影、图标和选中状态。
- 输入框、按钮、数据表、热力图、审批表单及各类占位状态。
- 浅色/深色、宽屏/窄屏和预览聚焦行为。

验证方法：

1. 固定同一示例数据、主题、视口、页面及交互状态；加载完成、动画稳定后截图。
2. 主桌面检查 1440×900、1280×800；窄屏检查 375×812。为方便比较，两站点使用相同视口和浏览器。
3. 保存参考截图、实现截图和差异图，逐页检查后修正。每次修正只重查相关画面，再执行必要回归。
4. 时间戳、运行 ID、真实性能数值等可变内容仅局部处理，记录排除区域；不遮蔽布局或主要内容来降低差异。
5. 同时参考像素差异和人工视觉检查；不能将单个像素差异比例直接宣称为“还原率”。
6. 中文固定 `zh-CN` 对照原型；英文使用同样的布局和 Token，在上述三个视口及明暗主题下检查并保存截图。语言入口与必要的英文换行按追加需求记录，不虚构英文参考图。

允许的差异：已确认评审修正、真实运行反馈替代 Mock、必要无障碍改进、窄屏溢出修复，以及新增功能入口。新增入口沿用已有视觉语言。所有允许差异应在视觉报告中逐项列明。

完成时不应有未解释的明显布局、字体、间距或组件样式偏差。不能仅凭“看起来差不多”结束，也不承诺浏览器字体栅格化等细节绝对一致。

## 6. 执行和验证顺序

1. 检查工作目录、工具和已有文件；建立工程约定及可持续更新的执行清单。
2. 验证实际 A2UI SDK/API/官方示例，确定适配边界和精确版本。
3. 建立参考站点与截图基线，提取可复用的样式、图标和布局参数；不把参考 Mock 逻辑当成正式 Runtime。
4. 按 M1–M4 实现，尽早做贯通的最小真实链路，再扩展组件、插件、API 与错误处理。视觉还原随每个页面实施，不全部堆到最后。
5. 每里程碑执行适用 lint/typecheck/unit/integration/E2E，并记录实际命令、通过数和失败项；后续增加插件、安全与视觉验证。
6. 完成端到端验收与逐页视觉修正；修复后做相关回归，最终执行交付检查。

测试验证真实行为：实际官方渲染、真实编译产物、实际预览实例与 Action。禁止用测试专用硬编码组件/伪造服务返回替代被测链路。

- `docs/ui/visual-verification.md`：各页面/状态、截图位置、差异和修正记录。

只有全部必需验收项通过，且视觉报告没有未解释的明显偏差，才能将 Goal 标记 complete。预算耗尽、阶段完成、部分测试通过、功能受阻均不等于目标完成。
